# CDPT V4 — Reproducibility Audit

Date: 2026-09-16  
Scope: V3 original/resource reruns, V4 Cora seed-0 repeat probe, the formal V4 Cora five-seed mechanism batch, and the V4 CiteSeer extension batch.

## Audit conclusion

The protocol is reproducible when PyTorch deterministic algorithms are enabled and `CUBLAS_WORKSPACE_CONFIG=:4096:8` is set before process start. Two independent V4 CDPT runs with the same Cora seed-0 configuration produced identical initialization, training-negative, batch-order, selected-checkpoint, RNG-state, validation-MRR, and test-MRR hashes. Runtime differed, so wall-clock time is treated as an execution measurement rather than a deterministic quantity. The formal Cora batch and CiteSeer extension each completed all 25 model runs with complete manifests; both used the locked non-strict mode and are therefore summarized as seed variation plus separately audited execution variation.

The historical V3 non-strict CUDA path was not bitwise reproducible across the original and resource-instrumented rerun. Its largest test-MRR difference was 0.013950 (B4, seed 2). Those batches are retained separately and are not merged into the V4 mechanism aggregate.

## V3 original versus resource rerun

The original performance batch is preserved under `AUTONOMOUS_MODEL_INNOVATION_V3/phase2_seed0/` and `AUTONOMOUS_MODEL_INNOVATION_V3/cora_five_seeds/seed1..seed4/`. The resource-complete reruns are under `AUTONOMOUS_MODEL_INNOVATION_V3/cora_measured/seed0..seed2/`.

| Check | Finding |
|---|---|
| Same model/data/config | Yes by recorded hashes and configuration fields; resource rerun changed instrumentation and output path only. |
| Same initialization | V3 did reset Python/NumPy/PyTorch before each construction; V3 did not record a full initialization-state hash. V4 adds that hash. |
| Training negatives | V3 uses `np.random.default_rng(seed*10000 + epoch)` for uniform negatives. V4 records the complete negative-array hash per epoch. |
| Batch order | V3 uses a manually seeded `np.random.default_rng(seed).permutation`; there is no DataLoader. V4 records the permutation hash per epoch. |
| Official evaluation candidates | Fixed HeaRT grouped candidates from the dataset artifact; V4 records their contribution in the data hash. |
| Test selection | False in every V3/V4 result used here; checkpoint is selected by validation MRR only. |
| Target-edge masking | `mask_pair_edges` is called before every encoder forward with `remove_target_edges=True`. |
| Largest V3 original/resource test-MRR difference | 0.0139500978, B4 seed 2. |

The V3 resource rerun therefore demonstrates execution noise in the non-strict path. It is not evidence of a model change. The V4 formal Cora batch is stored under `raw/mechanism_cora_v4run3/`, with the aggregate at `raw/mechanism_cora_v4run3/cora_v4_summary.json`.

## Randomness and nondeterminism inventory

- Python `random`, NumPy global RNG, PyTorch CPU RNG, and CUDA RNG are seeded by `seed_everything`.
- Uniform training negatives use an explicit NumPy `default_rng`; they are sorted before return, and V4 records the resulting array hash.
- Batch order is generated by an explicit NumPy `default_rng(seed).permutation`; there is no `DataLoader`, worker process, or implicit sampler in this runner.
- Dropout consumes the PyTorch RNG during training. The strict repeat covers this stream through exact final state and checkpoint hashes.
- HeaRT validation/test negative candidates are loaded from official fixed files; they are not resampled at evaluation.
- The encoder is a hand-written GCN/SAGE path using `index_add_`, `bincount`, and dense CUDA matrix operations. No PyG sparse convolution is used by this runner. The non-strict historical path can therefore show CUDA execution variation even when logical seeds and arrays agree.
- Enabling strict deterministic algorithms without a pre-set CUBLAS workspace failed before training with the documented CuBLAS configuration error. With `CUBLAS_WORKSPACE_CONFIG=:4096:8`, the strict CDPT probe completed and repeated bitwise.

## Reproducibility boundary

The strict probe establishes that the implementation can be made deterministic for the audited configuration. The formal V4 five-seed mechanism batch uses the same non-strict execution mode as V3 so that the locked training protocol is not changed midstream; any residual execution variation is reported separately from seed-to-seed model variation. The CiteSeer aggregate initially exposed a filename-prefix assumption in the analysis script; the raw JSON was intact, the loader was corrected to match dataset-independent seed/model suffixes, and the summary was regenerated without rerunning models. No result from a different code hash or resource rerun is silently merged into the formal aggregate.
