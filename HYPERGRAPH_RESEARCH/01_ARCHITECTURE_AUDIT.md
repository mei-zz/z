## Model path

| Component | Evidence | Finding |
|---|---|---|
| Target-edge masking | `src/dcdlp/models/dcdlp.py:68-74`, `src/dcdlp/models/node_encoder.py:14-28` | The union of pairs in a forward batch is removed from the undirected message edge list before encoding. |
| Encoder | `src/dcdlp/models/node_encoder.py:31-81` | Two configurable GCN or GraphSAGE layers, LayerNorm, ReLU and dropout. |
| Degree branch | `src/dcdlp/models/branches.py:21-35` | Uses endpoint degree summaries and an MLP scorer. |
| CN branch | `src/dcdlp/models/branches.py:38-180` | Pools common-neighbor node messages with sum/max, raw CN and optional AA/RA or train-fitted residual features. |
| Residual branch | `src/dcdlp/models/branches.py:182-195` | Uses endpoint product, absolute difference and sum of encoded node states. |
| Decoder | `src/dcdlp/models/dcdlp.py:86-109` | Additive degree + CN + residual + optional degree/CN interaction, or a concatenation MLP. |
| Loss/training | `src/dcdlp/train.py:527-646` | BCE link loss, optional legacy orthogonality/adversarial/intervention terms, gradient clipping and AdamW. |

DCDLP therefore has no explicit hyperedge/incidence object, and its only higher-order-looking structure is common-neighbor pooling. It does not currently distinguish a set-valued hyperedge message from ordinary pairwise propagation.

## Data and evaluation path

- `GraphDataset.train_graph()` in `src/dcdlp/data/loaders.py:56-74` constructs the message graph from `train_pos` only.
- Dataset validation checks feature shape, split disjointness, positive-union consistency and grouped-negative shape in `src/dcdlp/data/loaders.py:76-153`.
- Training negatives are regenerated by `_sample_train_negatives` in `src/dcdlp/train.py:119-130`. Standard evaluation uses generated uniform or degree-corrected negatives; `heart`/`ogb` uses official grouped candidates through `grouped_official_negatives` and `evaluate_split` in `src/dcdlp/train.py:309-399`.
- Ranking uses the average optimistic/pessimistic rank rule in `src/dcdlp/evaluation/ranking.py:13-19`; classification additionally reports AUC and AP.
- Checkpoint selection is validation-MRR only. The implementation now persists the selected validation record under `validation` in each result JSON; test metrics remain under `metrics` and are computed after selection.

## LPShift compatibility finding

The existing V7 audit is decisive for this round:

1. LPShift has a custom split and a saved message graph, not the ordinary OGB split.
2. The default LPShift message graph contains 17,880 canonical context edges that are not present in `train_pos` (`AUTONOMOUS_FAILURE_DRIVEN_RESEARCH/V7/DATA_PROTOCOL_AUDIT.md:37`).
3. Reusing `GraphDataset.train_graph()` would silently drop those edges (`AUTONOMOUS_FAILURE_DRIVEN_RESEARCH/V7/DCDLP_AA_BASELINE_AUDIT.md:42-52`).
4. LPShift also requires row-aligned `[num_positive, 250, 2]` candidate tensors and official target masking; replacing these with the native loader's generated negatives would change the benchmark.

Consequently no DCDLP or hypergraph number in this round is called an LPShift result. LPShift is `PROTOCOL_BLOCKED` until a protocol-preserving adapter stores `message_edge_index` separately from `train_pos`.

## Insertion point and leakage boundary

The implemented branch is inserted immediately after the target-masked node encoder and before the three DCDLP branches (`src/dcdlp/models/dcdlp.py:72-88`). It receives only the `message_edges` tensor already produced by `mask_pair_edges`; it does not receive labels, validation/test positives, candidate labels or future edges. This is safe for the standard split and is the intended boundary for a future LPShift adapter.
